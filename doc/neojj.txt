1. INTRODUCTION                                            *neojj-introduction*

NeoJJ is a Neovim plugin that provides integration with the Jujutsu (jj)
version control system. It offers an intuitive, interactive interface for
managing Jujutsu repositories without leaving Neovim.

NeoJJ is inspired by Neogit and provides similar functionality for the
Jujutsu version control system, including:

• Beautiful syntax-highlighted buffers
• Interactive status view with inline diffs
• Commit history browser with graph visualization
• Commit description editor
• Async operations for non-blocking UI
• Vim-style keybindings throughout

Open NeoJJ views (status, log and operation log) auto-refresh when the
repository changes externally — for example a `jj` command run in another
terminal, or a `jj git fetch`. NeoJJ watches the repository's operation heads
and reloads the affected views automatically, so you never see stale state. No
keybinding is involved; you can still refresh manually with `r` / <C-r>.

2. REQUIREMENTS                                            *neojj-requirements*

• Neovim >= 0.9.0
• Jujutsu >= 0.9.0 (the `jj` command-line tool)
• plenary.nvim - Required dependency for async operations

    :checkhealth neojj
<
It reports:

• Your Neovim version (warns if older than the minimum supported).
• Whether the `jj` executable is on your PATH, and its version (warns if
  older than the minimum supported).
• Whether plenary.nvim is available.

3. INSTALLATION                                            *neojj-installation*

Using lazy.nvim: >lua
    {
      "yourusername/NeoJJ",
      dependencies = {
        "nvim-lua/plenary.nvim",
      },
      config = function()
        require("neojj").setup()

        -- Optional keybindings
        vim.keymap.set("n", "<leader>js", "<cmd>JJ status<cr>")
        vim.keymap.set("n", "<leader>jl", "<cmd>JJ log<cr>")
        vim.keymap.set("n", "<leader>jd", "<cmd>JJ describe<cr>")
      end,
    }
<

Using packer.nvim: >lua
    use {
      "yourusername/NeoJJ",
      requires = { "nvim-lua/plenary.nvim" },
      config = function()
        require("neojj").setup()
      end
    }
<

4. COMMANDS                                                    *neojj-commands*

NeoJJ provides a unified `:JJ` command with subcommands:

                                                                          *:JJ*
:JJ [subcommand] [args...]
                With no subcommand, return to the view stack: raise the most
                recent NeoJJ view (log/status/file) from wherever you are. This
                is how you get back to a status view after opening a file from
                it. See |neojj-view-stack|.

                With a subcommand, execute it. Available subcommands:
                • status
                • log
                • oplog
                • describe
                • new
                • annotate
                • split

                                                                   *:JJ-status*
:JJ status [change_id] [split]
                Open the status buffer showing working copy changes or a
                specific change.

                Arguments:
                • `change_id` - Show status for a specific change/revision
                                (default: working copy)
                • `split` - Split type (optional)
                  - `horizontal` - Open in horizontal split
                  - `vertical` - Open in vertical split
                  - `tab` - Open in new tab

                Examples: >
                    :JJ status              " Working copy in current window
                    :JJ status horizontal   " Working copy in horizontal split
                    :JJ status abc123       " Specific change in current window
                    :JJ status @-           " Parent commit
                    :JJ status abc123 vertical  " Specific change in vertical split
<

                                                                      *:JJ-log*
:JJ log [split] [count]
                Open the log buffer showing commit history.

                Optional split argument (same as status) and an optional
                revision count that overrides the configured `log_limit` for
                this view. Either order is accepted.

                Examples: >
                    :JJ log
                    :JJ log vertical
                    :JJ log 50
                    :JJ log vertical 200
<

                                                                    *:JJ-oplog*
:JJ oplog [op_id] [split]
                Open the operation-log buffer showing jj's operation history
                (the universal undo/redo safety net). Each entry is a jj
                operation you can restore the whole repository back to.

                With an operation id, jump straight to that operation's
                detail view (the equivalent of `jj op show <op_id>`) instead
                of the log — the same view reached by pressing <CR> on an
                operation in the log.

                Optional split argument (same as status/log).

                Examples: >
                    :JJ oplog
                    :JJ oplog vertical
                    :JJ oplog tab
                    :JJ oplog aff62571bf72
                    :JJ oplog aff62571bf72 vertical
<

                                                                 *:JJ-describe*
:JJ describe [revision] [split]
                Edit the description for a commit.

                Arguments:
                • `revision` - Revision to describe (default: @)
                • `split` - Split type (optional)

                Examples: >
                    :JJ describe
                    :JJ describe @-
                    :JJ describe @ horizontal
<

                                                                      *:JJ-new*
:JJ new [revision]
                Create a new empty change.

                Arguments:
                • `revision` - Create new change after this revision (optional)

                Examples: >
                    :JJ new
                    :JJ new @
                    :JJ new qpvuntsm
<

                                                                 *:JJ-annotate*
:JJ annotate [filepath]
                Open the annotate buffer showing, for each line, the change
                that last modified it (jj's line-level blame).

                The annotation is displayed in a narrow vertical split to the
                left of the file, scroll-bound to the source window.

                Arguments:
                • `filepath` - File to annotate, relative to the repository
                               root (default: the current buffer's file)

                Examples: >
                    :JJ annotate              " Annotate the current file
                    :JJ annotate src/main.rs  " Annotate a specific file
<

                                                                    *:JJ-split*
:JJ split [revision]
                Interactively split a commit into two commits.

                Opens a terminal with jj's native interactive diff editor,
                allowing you to select which changes go into the first commit.
                The remaining changes stay in the second commit.

                Arguments:
                • `revision` - Revision to split (default: @)

                Examples: >
                    :JJ split           " Split current commit
                    :JJ split @-        " Split parent commit
                    :JJ split abc123    " Split specific revision
<

VIEW STACK                                                  *neojj-view-stack*

Drilling down through NeoJJ builds a stack of live views. A typical flow: >
    :JJ log            " open the log
    <CR>               " open the status view for the change at cursor
    <CR>               " (after expanding a diff) open the file at cursor
<
Each step keeps the previous view alive rather than re-rendering it, so its
cursor, folds and scroll position are preserved exactly.

To walk back up:
                • On a NeoJJ view (log/status), press `q` or `<Esc>` to pop one
                  frame and reveal the view beneath. Popping the last frame
                  closes the view.
                • From a file you opened out of a status view (a non-NeoJJ
                  buffer, so `q` is not remapped), run `:JJ` with no arguments
                  to return to the status view. `:JJ` returns to the top of the
                  stack from anywhere.

Only the log, operation-log, status and file views participate in the stack.
The describe, annotate and split-terminal views are transient and are not
stacked.

5. STATUS BUFFER                                                  *neojj-status*

The status buffer displays the current state of your working copy or any
specific change/revision, including:

• Change information (change ID, commit ID, description, author)
• Modified files with inline diffs
• Conflicts (if any)

When showing a specific change (e.g., `:JJ status abc123`), the buffer title
will include the change ID, and all operations will be relative to that
change instead of the working copy.

STATUS MAPPINGS                                          *neojj-status-mappings*

The following keybindings are available in the status buffer:

                                                      *neojj-status-navigation*
j                       Move cursor down
k                       Move cursor up

                                                         *neojj-status-display*
<Tab>                   Toggle diff expansion for file at cursor
<S-Tab>                 Toggle all file diffs
?                       Toggle help text

                                                         *neojj-status-refresh*
r                       Refresh status buffer
<C-r>                   Refresh status buffer

                                                         *neojj-status-actions*
<CR>                    Open file at cursor
d                       Describe current commit (edit description)
c                       Commit change: describe @ then jj new, landing on a
                        fresh empty working copy
n                       Create new change from current commit
f                       Run jj fix on the working copy (formats @)
t                       Tug: advance the closest bookmark up to @
P                       Push to remote (jj git push): prompts for all tracked
                        bookmarks, a specific bookmark, or this change (--change)
p                       Pull from remote (jj git fetch)
l                       Open log view
o                       Open operation log view

                                                           *neojj-status-close*
q                       Back: pop the view stack (reveal the view drilled down
                        from); closes the status buffer if it is the last frame
<Esc>                   Same as q
<C-c>                   Same as q

6. LOG BUFFER                                                        *neojj-log*

The log buffer displays commit history with a graph visualization. Each
commit shows:

• Graph visualization
• Change ID (abbreviated)
• Author information
• Timestamp
• Commit description

LOG MAPPINGS                                                *neojj-log-mappings*

The following keybindings are available in the log buffer:

                                                        *neojj-log-navigation*
j                       Move cursor down
k                       Move cursor up

                                                           *neojj-log-display*
<Tab>                   Toggle expanded details for commit at cursor
?                       Toggle help text

                                                           *neojj-log-refresh*
r                       Refresh log buffer
<C-r>                   Refresh log buffer

                                                           *neojj-log-actions*
<CR>                    Show commit details for commit at cursor
d                       Describe commit at cursor (edit description)
n                       Create new change after commit at cursor
e                       Edit change at cursor (make it the working copy)
f                       Run jj fix on the working copy (formats @)
t                       Tug: advance the closest bookmark up to @
b                       Bookmark management: opens a menu to create, move,
                        delete, rename, or track/untrack a bookmark relative to
                        the change at cursor
P                       Push to remote (jj git push): prompts for all tracked
                        bookmarks, a specific bookmark, or the change at cursor
                        (--change)
p                       Pull from remote (jj git fetch)
s                       Open status view
o                       Open operation log view
y                       Yank change ID for commit at cursor

                                                             *neojj-log-close*
q                       Back: pop the view stack (reveal the view drilled down
                        from); closes the log buffer if it is the last frame
<Esc>                   Same as q
<C-c>                   Same as q

7. OPERATION LOG BUFFER                                            *neojj-oplog*

The operation-log buffer displays jj's operation history: every operation that
has mutated the repository (commits, describes, rebases, pushes, undos, …). It
is jj's universal safety net — you can restore the whole repository back to any
listed operation, which is what makes destructive commands safe to run.

Each operation shows:

• Graph visualization (`@` marks the current operation)
• Operation ID (abbreviated)
• The user who performed it
• Start timestamp
• Operation description

Open it with |:JJ-oplog| or |neojj.jj_oplog()|.

Press <CR> on an operation to drill into a read-only view of its details and
diff (the equivalent of `jj op show <op_id>`); q/<Esc>/<C-c> returns to the
operation log, l opens the commit log, and <C-r> refreshes.

OPLOG MAPPINGS                                            *neojj-oplog-mappings*

The following keybindings are available in the operation-log buffer:

                                                      *neojj-oplog-navigation*
j                       Move cursor down
k                       Move cursor up

                                                         *neojj-oplog-display*
?                       Toggle help text

                                                         *neojj-oplog-refresh*
<C-r>                   Refresh operation log

                                                         *neojj-oplog-actions*
<CR>                    Show the details of the operation at cursor
                        (jj op show) in a new drill-down view; press q/<Esc>
                        to return to the operation log
r                       Restore the repository to the operation at cursor
                        (jj op restore), after a confirmation prompt
u                       Undo the last operation (jj undo), after a confirmation
                        prompt
y                       Yank the operation ID at cursor to the system clipboard
l                       Open the commit log view

                                                           *neojj-oplog-close*
q                       Back: pop the view stack (reveal the view drilled down
                        from); closes the oplog buffer if it is the last frame
<Esc>                   Same as q
<C-c>                   Same as q

8. DESCRIBE BUFFER                                              *neojj-describe*

The describe buffer is used to edit commit descriptions. It behaves similarly
to Git commit message editors, with help text displayed as comments.

DESCRIBE MAPPINGS                                      *neojj-describe-mappings*

The following keybindings are available in the describe buffer:

                                                      *neojj-describe-actions*
<C-s>                   Submit description (normal/insert mode)
<C-c><C-c>              Submit description (like git commit)
ZZ                      Submit description (vim-style save and quit)

                                                       *neojj-describe-abort*
<C-c><C-q>              Abort editing (discard changes)
ZQ                      Abort editing (vim-style quit without saving)
q                       Close with confirmation if modified

                                                    *neojj-describe-commands*
:w                      Submit description
:wq                     Submit description
:q!                     Abort editing

Note: Only lines starting with 'JJ:' are treated as help comments and will be
excluded from the final description. Ordinary lines starting with '#' (such as
Markdown headings or issue references like '#123') are preserved.

9. ANNOTATE BUFFER                                       *neojj-annotate-buffer*

The annotate buffer shows line-level blame for a file: for every line of the
source, it displays the change that last modified it. It opens as a narrow
vertical split to the left of the file and is scroll-bound to the source
window, so scrolling either side keeps the annotations aligned.

Open it with |:JJ-annotate| or |neojj.jj_annotate()|.

ANNOTATE MAPPINGS                                      *neojj-annotate-mappings*

The following keybindings are available in the annotate buffer:

                                                       *neojj-annotate-actions*
<CR>                    Open the change at cursor in a status buffer
y                       Copy the change ID at cursor to the system clipboard
?                       Toggle help text

                                                         *neojj-annotate-close*
q                       Close annotate buffer
<C-c>                   Close annotate buffer
<Esc>                   Close annotate buffer

10. CONFIGURATION                                         *neojj-configuration*

NeoJJ can be configured by passing options to the setup function. Calling
setup() is optional: NeoJJ registers |:JJ| and its highlights on load, so the
plugin works with no configuration. Call setup() only to override a default.

SETUP OPTIONS                                          *neojj-setup-options*

>lua
    require("neojj").setup({
      log_level = vim.log.levels.INFO,  -- Set log level
      log_limit = 100,                  -- Default revisions shown in the log
      diff = {
        inline = true,                  -- Inline vs. side-by-side file diffs
        fold = true,                    -- Collapse unchanged regions in the
      },                                -- side-by-side float
    })
<

                                                        *neojj-setup-type*
NeoJJ exposes a `NeoJJSetupOptions` type. If you use lua-language-server,
annotate your options table to get completion and have typo'd keys flagged in
your editor before they silently do nothing: >lua
    ---@type NeoJJSetupOptions
    local opts = { log_limit = 200, diff = { inline = false } }
    require("neojj").setup(opts)
<

                                                            *neojj-log-level*
log_level               Set the logging level for NeoJJ. Available levels:
                        • vim.log.levels.DEBUG
                        • vim.log.levels.INFO (default)
                        • vim.log.levels.WARN
                        • vim.log.levels.ERROR

                                                            *neojj-log-limit*
log_limit               Default number of revisions shown in the log view
                        (default: 100). Override per invocation with the
                        count argument to |:JJ-log| (e.g. `:JJ log 50`).

                                                            *neojj-diff-inline*
diff.inline             How <Tab> renders a file's diff in the status view
                        (default: true).
                        • true  - expand a unified diff inline, under the file.
                        • false - open a side-by-side diff in two adjacent
                          floating windows using Neovim's native diff mode
                          (parent revision left, shown revision right). Inside
                          the floats, <Tab>, q or <Esc> close both windows and
                          return to the status view; only one pair is open at a
                          time. Added files show an empty left side, deleted
                          files an empty right side, and binary files report a
                          short message instead of diffing.
                        Note: <S-Tab> (toggle all diffs) is inline-only.

                                                            *neojj-diff-fold*
diff.fold               Whether the side-by-side float starts with its
                        unchanged regions collapsed (default: true).
                        • true  - collapse unchanged regions, like vimdiff.
                        • false - show the whole file, unchanged regions and
                          all.
                        No effect when diff.inline is true.

CUSTOM KEYBINDINGS                                      *neojj-keybindings*

You can set up custom keybindings for NeoJJ commands:

>lua
    -- Basic keybindings
    vim.keymap.set("n", "<leader>js", "<cmd>JJ status<cr>")
    vim.keymap.set("n", "<leader>jl", "<cmd>JJ log<cr>")
    vim.keymap.set("n", "<leader>jd", "<cmd>JJ describe<cr>")

    -- Smart keybinding: JJ in jj repos, fallback to git tool
    vim.keymap.set("n", "<Leader>jj", function()
      local util = require("neojj.lib.jj.util")
      if util.is_jj_repo() then
        require("neojj").jj_status()
      else
        vim.cmd("Git")  -- or your preferred git tool
      end
    end, { desc = "Open VCS status" })
<

11. HIGHLIGHTS                                                *neojj-highlights*

NeoJJ defines the following highlight groups. They link to standard Neovim
highlight groups by default but can be customized.

HIGHLIGHT GROUPS                                      *neojj-highlight-groups*

NeoJJTitle              Buffer titles
                        Default: links to |hl-Title|

NeoJJSectionHeader      Section headers
                        Default: links to |hl-Function|

NeoJJFileAdded          Added files in status/diff
                        Default: links to |hl-DiffAdd|

NeoJJFileModified       Modified files in status/diff
                        Default: links to |hl-DiffChange|

NeoJJFileDeleted        Deleted files in status/diff
                        Default: links to |hl-DiffDelete|

NeoJJDiffAdd            Added lines in diffs
                        Default: links to |hl-DiffAdd|

NeoJJDiffDelete         Deleted lines in diffs
                        Default: links to |hl-DiffDelete|

NeoJJLogGraph           Graph characters in log view
                        Default: links to |hl-Special|

NeoJJLogBookmark        Bookmark names in the log view
                        Default: links to |hl-Keyword|

NeoJJLogTag             Tag names in the log view
                        Default: links to |hl-Keyword|

NeoJJOplogGraph         Graph characters in the operation-log view
                        Default: links to |hl-Special|

NeoJJConflict           Conflict markers
                        Default: links to |hl-Error|

NeoJJHelpText           Help text and comments
                        Default: links to |hl-Comment|

CUSTOMIZING HIGHLIGHTS                                  *neojj-custom-highlights*

After calling setup, you can customize highlight groups:

>lua
    require("neojj").setup()

    -- Override with custom colors
    vim.api.nvim_set_hl(0, "NeoJJTitle", { fg = "#ff0000", bold = true })
    vim.api.nvim_set_hl(0, "NeoJJDiffAdd", { fg = "#00ff00" })

    -- Or link to different groups
    vim.api.nvim_set_hl(0, "NeoJJTitle", { link = "Keyword" })
    vim.api.nvim_set_hl(0, "NeoJJSectionHeader", { link = "Type" })
<

Note: Highlights are automatically reapplied when the colorscheme changes.

12. LUA API                                                          *neojj-api*

NeoJJ provides a Lua API for programmatic access to its functionality.

SETUP FUNCTION                                                  *neojj.setup()*

neojj.setup({opts})
                Initialize NeoJJ with configuration options.

                Parameters: ~
                    {opts}  (table|nil) Configuration options
                            • log_level: Log verbosity level
                            • log_limit: Default revisions shown in the log
                            • diff.inline: Inline vs. side-by-side file diffs
                              (see |neojj-diff-inline|)
                            • diff.fold: Collapse unchanged regions in the
                              side-by-side float (see |neojj-diff-fold|)

                Example: >lua
                    require("neojj").setup({
                      log_level = vim.log.levels.INFO,
                      log_limit = 100,
                      diff = { inline = true, fold = true },
                    })
<

BUFFER FUNCTIONS                                           *neojj-api-buffers*

neojj.jj_status({dir}, {revision}, {split})                *neojj.jj_status()*
                Open the status buffer for the working copy or a specific
                revision.

                Parameters: ~
                    {dir}      (string|nil) Directory path (default: cwd)
                    {revision} (string|nil) Revision to show (default: working copy)
                    {split}    (string|nil) Split type: "horizontal", "vertical",
                               "tab", or nil for replace

neojj.jj_log({dir}, {split}, {limit})                         *neojj.jj_log()*
                Open the log buffer.

                Parameters: ~
                    {dir}   (string|nil) Directory path (default: cwd)
                    {split} (string|nil) Split type
                    {limit} (number|nil) Revisions to show (default: the
                            configured |neojj-log-limit|)

neojj.jj_oplog({dir}, {split})                             *neojj.jj_oplog()*
                Open the operation-log buffer showing jj's operation history.

                Parameters: ~
                    {dir}   (string|nil) Directory path (default: cwd)
                    {split} (string|nil) Split type

neojj.jj_describe({dir}, {revision}, {split})            *neojj.jj_describe()*
                Open the describe buffer to edit a commit description.

                Parameters: ~
                    {dir}      (string|nil) Directory path (default: cwd)
                    {revision} (string|nil) Revision to describe (default: "@")
                    {split}    (string|nil) Split type

neojj.jj_new({dir}, {revision})                              *neojj.jj_new()*
                Create a new empty change.

                Parameters: ~
                    {dir}      (string|nil) Directory path (default: cwd)
                    {revision} (string|nil) Create new change after this
                               revision (optional)

neojj.jj_annotate({dir}, {filepath})                    *neojj.jj_annotate()*
                Open the annotate buffer showing line-level blame for a file.

                Parameters: ~
                    {dir}      (string|nil) Directory path (default: cwd)
                    {filepath} (string|nil) File to annotate, relative to the
                               repository root (default: the current file)

neojj.jj_split({dir}, {revision})                          *neojj.jj_split()*
                Open a terminal to interactively split a commit.

                Uses jj's native diff editor to select changes for the
                first commit. Remaining changes go to the second commit.

                Parameters: ~
                    {dir}      (string|nil) Directory path (default: cwd)
                    {revision} (string|nil) Revision to split (default: "@")

REPOSITORY FUNCTIONS                                    *neojj-api-repository*

neojj.get_repo({dir})                                      *neojj.get_repo()*
                Get a repository instance for the given directory.

                Parameters: ~
                    {dir} (string|nil) Directory path (default: cwd)

                Returns: ~
                    Repository instance with methods:
                    • :is_jj_repo() - Check if directory is a jj repo
                    • :refresh() - Refresh repository state
                    • :get_working_copy() - Get working copy information
